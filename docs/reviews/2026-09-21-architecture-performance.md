# 架构与性能评估

评估日期：2026-09-21。当前工作树 main@454177d，manifest 为 1.2.1；补充检查本地远端引用 origin/feat/20260521@1e19832（模块化、侧栏、AI Worker）。未联网 fetch 分支，不能断言对应远端当前最新提交。未修改业务代码，未调用外部模型或操作 Google Maps 保存列表。

## 优先级与证据

### P1：任务状态不应依赖 UI 页面存活

main build/popup.js:625、782：队列游标、暂停、统计与运行锁均在 popup 内存里。新版 build/src/marking/runner.js 的同类循环仍在 UI 中；build/background.js 只负责侧栏配置和打开。关闭 popup 后后续调度丢失；popup 与侧栏有各自状态，可能对同一 tab 同时执行。

建议：由后台统一接收任务并维护按 tab 的独占任务标识；任务队列、游标、每项状态与恢复信息持久化；content script 执行单项 DOM 操作并确认结果；UI 订阅状态。后台也可能终止，不能简单把长循环搬到 service worker：设计事件驱动推进、检查点、在途项目重验和恢复入口。

Chrome 官方说明 popup 失焦会关闭：https://developer.chrome.com/docs/extensions/develop/ui/add-popup
Service worker 生命周期与状态持久化：https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle

### P1：标注目标的正确性与完成判定

main build/popup.js:1225：只要地点在任意列表中呈 Saved，就直接 skipped，未检查目标列表。新版 build/src/marking/content.js 保留相同逻辑。main:1243 还以 includes 匹配列表名，目标“WHV”可能命中“WHV 旧列表”。main:1263 只等通用 Saved 按钮，没有验证目标列表最终勾选状态。

建议：先确认当前搜索结果对应本次邮编，再定位目标列表独立标题，精确匹配并检查其勾选状态；有歧义就报错。选中后验证目标状态再计成功。重试之前重新检查目标列表，避免把已经完成的勾选操作反向取消。

本地 DOM stub 复现：Saved 按钮存在时返回 already_saved，打开保存菜单次数为 0。

### P1：固定等待放大批处理延迟

main build/popup.js:1210、1231；新版 content.js 同样固定等待搜索 2 秒、菜单 1.5 秒。页面快时浪费等待，慢时可能误读上一地点或失败。

建议：以搜索结果身份变化、目标详情可用、菜单可见、保存状态确认作为步骤条件；有界轮询或限定范围 MutationObserver，超时后清理监听。保留合理限速；同一 Maps tab 串行执行。类别全量操作改为可筛选、预览、分批、取消、断点续跑。

### P1：AI 路由缺少异常隔离和延迟预算（新版）

worker/src/aiRouter.js:98、139：fetch 无主动超时；316：直接 await provider，未捕获网络异常。349：非指定重试状态直接结束整个链，包括单个 provider 鉴权失败。build/src/advisor/cloudRouter.js 的客户端 fetch 也无主动超时。

本地模拟首个 provider fetch 抛 TypeError：routeAiChat 向外抛错；已配置 Workers AI 备用调用数为 0。

建议：每次上游调用有超时、整个请求有总期限和最大尝试次数；区分输入无效、上游配置错误、限流、瞬时网络错误；服务商故障可继续其他服务商；取消信号贯穿客户端和代理。增加故障冷却、耗时及错误类别指标，避免每次都重试已知故障上游。模型清单可配置；本次未验证各模型在线可用性。

### P2：AI 缓存并发覆盖（新版）

build/src/advisor/cache.js 的 getCachedLlm 和 putCachedLlm 都执行整桶 read-modify-write，连命中读取都会回写 lastUsed。单次 set 不能保证整个读改写序列原子性。

本地模拟两个并发 put 写 a、b：最终仅剩 b。

建议：由后台统一串行处理缓存变更，或用具备事务能力的存储。容量仅 30 条，优先选简单方案；避免每次命中全桶写入。缓存键加入 prompt、规则与输出 schema 版本，区分真实路由模式与配置意图。

### P2：规则数据、语言和计算耦合

main build/popup.js:285：每次资格查询创建规则对象、数组和闭包，结果携带显示文案。690：每个类别首次扫描 9800 个候选，调用全部规则。1099：输入事件同步重算完整批量摘要。

本机 Node 单次冷运行类别查询约 27–71 ms，仅用于量级判断，不等同浏览器性能；相比小时级标注流程属于次要问题。

建议：规则成为单一静态数据源，计算只返回类别 ID；UI 单独翻译；一次建立类别索引或直接展开对应类别范围，并为批量摘要增加短防抖。保留 4 位邮编字符串：当前 parsePostcodesInput('0872') 返回数字 872，随后原样传入搜索。规则数据记录来源、版本和更新时间；本次未审查签证政策准确性。

### P2：发布基线与验证缺口

README 描述 1.6.0，但 main manifest 为 1.2.1，main 缺少新版源码。已有模块化分支应作为后续迁移评估的输入，避免在旧版重复拆分。此次检查未发现现成测试套件。

建议：明确发布分支，从同一提交产出扩展包、版本与文档；CI 校验 manifest 引用文件、版本一致性、语法及核心回归。新版已经拆文件，但 runner 仍引用 UI DOM、语言包、存储与执行逻辑，应继续拆开职责，而非追求更多文件。

## 建议目标结构

- UI：popup / side panel，只提交命令与展示状态。
- 任务协调模块：按 tab 独占、任务快照、恢复、暂停、取消、统计。
- Maps adapter：搜索并确认结果、精确定位列表、保存及结果验证；隐藏 DOM 选择器。
- 规则模块：纯计算接口，静态规则版本与邮编格式校验。
- AI 推荐模块：统一结果 schema、输入归一化、缓存与本地回退。
- Worker 路由：provider adapter、超时预算、错误归类、冷却与观测。

无需为当前规模引入微服务或重型前端框架。优先修任务可靠性与标注正确性，再优化等待与路由，最后处理规则计算和工程组织。

## 验证与边界

已完成：main popup.js 的 Node 语法检查；邮编类别计数和冷运行计时；Saved 提前跳过的 DOM stub；新版 AI 网络异常不回退模拟；新版缓存并发覆盖模拟。

尚未完成：登录态 Maps 端到端、弹窗关闭及后台终止恢复实测、真实 AI 上游延迟/负载测试。上述 mock 证明对应分支逻辑，不证明当前 Google Maps DOM 与选择器兼容。

建议后续验收优先覆盖：关闭再打开 UI 能恢复任务；popup 与侧栏同时启动不会双跑；已在其他列表的地点可加入目标列表；同名子串不误选；慢速搜索不会标注旧地点；网络超时能切换且总时长受控；并发缓存写入无丢失。
